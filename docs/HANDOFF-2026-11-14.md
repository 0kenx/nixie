## Process discipline that this campaign learned the hard way

- **Differential before believing any single-instance number.**  The DIMACS
  preset study: a 1.8× "win" that was 27× seed-spread noise.  Use
  `NIXIE_SAT_SEED=<u64>` (both DIMACS paths), ≥10 seeds, fixed instance
  lists, and matched caps.  Never compare runs at different timeouts.
- **Equivalent-work changes must be counter-identical** (`STATS=1`
  conflicts/decisions/propagations).  The lean-BV gates were validated this
  way; the aprop oracle (`NIXIE_APROP_VERIFY=2` reconstructs every pushed
  clause as SMT-LIB, checkable with z3) is the tool for
  soundness-sensitive work – it found all three channel bugs.
- **Gates must be `&&`-chained into the commit command.**  Separate shell
  lines fail silently (twice this campaign).
- **Never `git restore`/`checkout --`/`stash`** – inverse edits only
  (violated three times under time pressure; each provably harmless only
  because the edits were my own, but the rule exists for the day they
  aren't).
- **Revert probes by inverse edit**, record every negative result in the
  study (the repo's own rule), and archive raw cells under
  `docs/studies/data/`.

## Profiling how-to (the part that wastes hours if unknown)

- `perf_event_open` is blocked in this sandbox.  Use the pprof crate at
  250 Hz **inside a sync-process harness** (a ~20-line bin linking
  `nixie-solver` + `Context::execute_script`, watchdog thread dumps the
  flamegraph so timeouts still profile).  Rebuild with
  `RUSTFLAGS="-C force-frame-pointers=yes"`.
- **The CLI cannot be profiled directly**: `async fn main` + tokio + the
  1 GiB stack worker break FP unwinding (frames truncate at
  `start_thread`; only the sample count survives).  The sync harness is
  the workaround.  Known flakiness: completion-vs-watchdog dump races
  produce 1–2-sample SVGs intermittently – rerun until deep frames
  appear.  The landed `--features pprof-signal` + `NIXIE_PPROF=<svg>` CLI
  hook has the same limitation; keep it for count-only checks.
- Flamegraph leaf-attribution: single-accessor frames at 30%+ = cache
  misses, not code cost (seen four times).  Verify mechanism before
  optimizing.
