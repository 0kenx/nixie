## Where things stand

The finite-bag (multiset) theory is **landed and fuzz-clean**: the
SMT-LIB bags surface parses and type-checks, every constraint reduces to
arithmetic over `bag.count`, verdicts agree with CVC5 1.3.4 on a
~4100-case differential campaign (0 mismatches at the end; every wrong
verdict the campaign found along the way is closed with a regression),
and `get-model`/`get-value` print count-driven bag values.

- **Surface** (`nixie-core`): `(Bag T)` sorts; `(bag e n)` (the make
  constructor), `bag.union_max` / `union_disjoint` / `inter_min` /
  `difference_subtract` / `difference_remove` / `member` / `subbag` /
  `count` / `card` / `setof`; `(as bag.empty (Bag T))`. Twelve
  TermKinds, builders with CVC5-`bags_rewriter` normalizations
  (including the lattice family and the negative-multiplicity clamp),
  `Value::Bag` with iterative Clone/Debug/Display (prints re-readable
  `bag.union_disjoint` chains). `bag.choose`/`map`/`filter`/`all`/
  `some`/`fold`/`partition` are honest parse-level rejections.
- **Decision procedure** (`nixie-solver/src/solver/bag_theory.rs`): the
  count reduction — for every (ground element, compound bag) pair the
  pointwise identity as an equation the arithmetic solver owns;
  membership/subbag/extensional-equality through those ints;
  `@bag_ext_*` witness skolems for the negated directions (the set
  arc's `@set_ext_*` discipline); cardinality as a de-duplicated sum
  over the known elements plus a nonnegative slack for *opaque* bags
  only, with `a = b → |a| = |b|`, `a ⊑ b → |a| ≤ |b|`, and per-operator
  card propagation (exact for `⊎`, upper bounds otherwise);
  `bag.count` argument-congruence over element pairs. Element lists are
  built from the count/member atoms **and** every bag term's support
  (the `bag.make` operands), so equalities between compounds — which
  mention no count term — are not silently vacuous.
- **Models** (`nixie-solver/src/solver/bag_model.rs`): a bag's value is
  fully determined by the arithmetic counts — no mints or pools — and
  assembles as the canonical `bag.union_disjoint` of `(bag e n)` cells,
  grouped by **resolved element value** (the witnesses merge into the
  cell they value; disagreeing counts decline the bag honestly).
  Cardinality is verified against the arithmetic solver's word before
  publishing; the count/card readback makes `(get-value ((bag.count …)`
  answer with numbers, and *query-only* count/card/member fold from the
  installed value (evaluation of a verified object — the same contract
  as the rel on-demand pass). CVC5's negative-multiplicity clamp holds
  end to end: literal folds to `bag.empty`, symbolic clamps through the
  `n ≥ 1` guard.
- **Tests**: 29 in `finite_bags_core.rs` (identities, extensionality,
  cardinality incl. the closed/opaque slack split, clamps, models,
  queries, scope, and one regression per fuzz find). Nothing ignored.

## The wrong verdicts found and closed (each has a regression)

1. **Closed compounds carried cardinality slack** (slice one, `bedae910`):
   `|(1:3) ⊎ (2:1)| = 5` answered `sat` — the slack exists for *opaque*
   bags' unknown support; a closed compound's support is exactly its
   makes. `bag_is_closed` splits the two.
2. **Equalities between compounds were vacuous** (slice one): the
   element list came only from count/member atoms, so
   `(bag 1 2) = (bag 1 3)` saw an empty list. Fixed by collecting every
   bag term's support.
3. **Opaque counts could go negative** (slice two, `25ac4e4c`):
   `count(1,b) = -3 ∧ |b| = -3` answered `sat` — multiplicities are
   nonnegative; the axiom was missing (closed compounds derive it
   through the clamped identities).
4. **`bag.count` had no argument congruence** (slice three, `7ebf2ffe`):
   the purified encoding gives each count term its own integer column
   with no tie (an `apply` gets it from theory combination);
   `¬subbag((1:3), b) ∧ count(1,b) ≥ 5` answered `sat`. Fixed with the
   set theory's pair-congruence pattern.
5. **No card propagation through the slack** (slice three): `b = ∅ ∧ |b| = 1`
   and `b ⊑ ∅ ∧ |b| = 2` answered `sat` — the per-element equations
   cannot see an opaque bag's unknown support; `equality ⇒ equal card`
   and `subbag ⇒ bounded card` (rules the set theory always had) close
   both.
6. **The counting sum double-counted equal-valued spellings** (slice
   three; a false *unsat* the moment rule 5 landed): the witnesses
   usually equal a real element — their consistency axioms force it —
   and summing every spelling counted one cell twice, so a bag pinned
   to a closed value forced its slack to absorb the duplicate and
   pinned the witnesses away from the values the disequality
   directions needed. Fixed with the set theory's dedup guards; the
   model's cardinality verification likewise checks the installed
   (deduplicated) cells.
7. **Missing lattice rewrites** (slice three): `dsub(c, umax(c, (x:1)))`
   kept an unknown-support slack past its true emptiness;
   `|(1:3) ⊎ (x:1) \ c|`-shapes answered `sat`. The builder gained
   CVC5's family: `a ⊓ (a ⊎ z) = a` (both unions, both orders),
   `a ⊎ (a ⊓ z) = a`, `a \ (a ⊎ z) = ∅`, `(a ⊎max z) \ a = z \ a`.
8. **The both-even ite parity bug** (`c0998491`) — *pre-existing, in the
   core, not the bag code*: `(assert (= (ite (= 3 x) 2 0) 2))` answered
   **unsat** (reproduced on `4ade3b1e`, before any bags work).
   `build_xor_lemma` returned the bare rhs constant for an empty
   literal chain instead of `false = c`, so a column whose ite branches
   agree in parity (both even) asserted `false` as a ground unit.
   Found by this arc's fuzz campaign (the both-even signature was the
   tell); fixed same-session, with the pinning unit test corrected.

## The fuzz harness (regenerate, don't rediscover)

The differential campaign is a ~90-line Python generator: small random
formulas over the landed fragment (elements 0–3 plus a variable,
multiplicities −1..3, bags to depth 2, 2–4 assertions mixing
count/member/subbag/equality/card atoms), nixie vs CVC5 1.3.4, seeds for
reproducibility, per-file cleanup (the disk filled once mid-campaign —
see environment notes). It found every bug above except the first two.
The shape to know: **count identities fold to `ite(e = y ∧ n ≥ 1, n,
0)`**, so the campaign exercises the whole ite/arithmetic/congruence
stack, which is how it caught the core parity bug. Recreate it before
extending the fragment — it is the cheapest soundness instrument this
arc had.

## Open chores (none blocking)

1. **`bag.choose`** — the next operator by value. CVC5 semantics:
   `choose(b)` returns an element of `b`; `b ≠ ∅ → count(choose(b), b)
   ≥ 1`; congruence `a = b → choose(a) = choose(b)`. The set arc's
   `set.choose` machinery (member axioms, pair congruence, counting
   interaction — `theory_finite_set_size` in Z3) is the template.
2. **`bag.map` / `bag.filter` / `bag.fold`** — need function handling;
   for `define-fun`-ground bodies the reduction can substitute
   (`count(y, map(f, b)) = Σ_{f(x)=y} count(x, b)` over the known
   elements; `count(x, filter(P, b)) = ite(P(x), count(x,b), 0)`).
   Uninterpreted functions need EUF cooperation — study CVC5's
   `bag_solver.cpp` first.
3. **Subbag `get-value` folding** — fold `bag.subbag` queries from
   installed values like count/member already do (pointwise ≤ over the
   union of cells).
4. **Perf on deep compounds**: nested operators produce deep ite chains
   in the count identities; adversarial shapes can take tens of seconds
   of search (honest answers, no wrongness). If the corpus ever grows
   bag problems, that is the first place to measure.
5. **`MAX_BAG_ELEMENTS = 24`** cap re-measurement, together with the set
   caps, once the TLA+ corpus runs green.
