## What landed

### 1. `bag.fold` — the last bag operator (queue item 1)

The reference semantics, read from CVC5 1.3.4 (`bag_reduction.cpp:
reduceFoldOperator`, `bags_rewriter.cpp: postRewriteFold`,
`bags_utils.cpp: evaluateBagFold`, the type rule in
`theory_bags_type_rules.cpp`): `f : (-> T1 T2 T2)` takes its **element
first, accumulator second**; `fold(f, t, (y:n)) = f(y, f(y, … f(y, t) …))`
with `n` applications. CVC5's skolem/bounded-quantifier reduction (for
opaque domains) is not compilable to this eager reduction — the landing
is the ground-multiset unroll the handover sketched:

- **Parse** (`nixie-core`): `open_named_head` intercepts `(bag.fold f t b)`
  with the binary-function operand parsed like the fp rounding modes; the
  full CVC5 type rule enforced (`f` binary, second arg sort = codomain,
  init : T2, bag of T1). `bag.partition` stays an honest rejection with a
  pointer (tuple-of-bags output).
- **Term**: `TermKind::BagFold { func, init, bag }` (result sort =
  init's), builder folds `fold(f, t, ∅) = t`, and the exhaustive-match
  discipline walked the change through every layer (traversal, hash,
  stats, structural/alpha equality + a new `shape::fold_args`, sort
  inference, congruence, rewriter, bitblast, substitution, ematching ×2,
  printers ×2, nelson-oppen, encode/encode_guards/skolem_candidates/
  track_theory_vars, model_eval, mbqi).
- **Reduction** (`bag_theory.rs`): a ground multiset (`∅`, `(bag y n)`
  with numeral `n`, `⊎`, under ites) unrolls into the finite application
  chain, iteratively (explicit stacks, no native recursion). A multiset
  with **two or more distinct element spellings** requires the
  **exchange law** `f(e1, f(e2, a)) = f(e2, f(e1, a))` — proved by a new
  sound AC-canonicalizer (`ac_canonical`: flatten+sort the AC families;
  equal canonical forms are a semantic-equality proof, and the form is
  never asserted). Declined folds stay **free** (every `Unsat` stays
  sound — the constraint set only got weaker) with guarded ties along
  surveyed bag-equality atoms (`atom → fold(a) = fold(b)`), so a fold
  over a variable pinned to a closed compound takes the closed value.
- **Models** (`bag_model.rs`): the **declined-fold certification** — a
  domain-declined fold's faithful value is synthesized from its bag's
  assembled cells and installed, then every assertion mentioning a
  declined fold must evaluate true (`eval_in_model_outcome`; the gate is
  read after `build_model`, inside `check`); an **order-sensitive** fold
  (exchange law unproved over several spellings) degrades
  *unconditionally* — CVC5 answers those through one fixed internal
  order, and exhibiting any particular order here would disagree with it
  half the time (the CORRECTION lesson of `2026-09-18-bags-all-some.md`:
  treat layout-dependent verdicts with suspicion). The false-`sat` the
  naive free encoding would give (`min`-fold over a free bag pinned
  above its init) is exactly what the certification catches.
- `bag_fun_defs` generalized to `BagFunDef { params, body }` so binary
  `define-fun`s inline per (element, accumulator) pair — the same
  call-site substitution the parser performs.

**Verification beyond the bar:** `bench/differential/bag_fold_fuzz.py`
(kept in-tree) — CVC5 1.3.4 as oracle, the honest comparator; 4 seeds ×
150–200 (20260919–20260925): **0 mismatches**. The one mismatch the
first run found (fold under `f(x,a) = x`, our order-witness vs CVC5's
fixed order) drove the order-sensitive unconditional degrade — the
generator's shapes now cover AC and non-AC functions, declared
combinators, symbolic elements, ite domains, and fold↔card/member
interaction. 12 new tests in `finite_bags_core.rs`.

### 1b. A latent congruence-identity bug fixed on the way

`equality_propagation.rs`'s `OperatorIdentity` carried `symbol: None`
for `bag.map`/`bag.filter`: `map f b` and `map g b` over equal domains
shared one identity, so EUF congruence would identify two different
images — a false equality waiting for a path that reaches it. All three
fun kinds now carry their symbol (and `bag.map` its codomain). The
end-to-end regression (`map_under_different_functions_is_not_congruence_identified`)
passes with the fix; it also passed with the fix temporarily reverted,
so the current pipeline purifies these terms before that layer — the
arms are correct-by-construction defense in depth. (Related quirk,
NOT changed: `structurally_equal`/`alpha_equivalent` conservatively
return `false` for two `BagMap`/`BagFilter` terms — the payload-carrying
kinds sit in the plain-unary arm whose `shape::unary_arg` returns
`None`. Only ever an optimization loss; noted here so the next reader
doesn't rediscover it.)
