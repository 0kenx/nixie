## Method

1. Enumerated every function/struct/enum/const **added** by upstream in each
   range, per file, and checked each symbol for presence anywhere in the fork
   (`rg --type rust` over all library crates). ~230 symbols audited per range.
2. For every ABSENT symbol, located the fork's equivalent by capability (the
   fork renamed/reorganized most of upstream's v0.3.2 module splits).
3. Re-verified each of the port study's "already present", "ported", and
   "deliberately not ported" dispositions against the current tree, and each
   **refuted** item's preconditions.
4. Read the in-line diffs of perf-sensitive files upstream touched
   (`propagate.rs`, `clause.rs`, `learn.rs`, `search_ext.rs`) to catch
   expression-level changes a symbol audit cannot see.

## Findings — two unported items, both ported this session

### 1. `nixie-proof/src/visualization.rs`: the JSON writer's Theta(d²) live-heap defect (upstream v0.3.3)

The only genuine unported **optimization** found. The fork's `write_json_node`
still built its structural delimiters (`]`, `}`, `},`, `{`) as fully-indented
`String`s pushed *below* the child frame — upstream's pre-fix shape — so a
chain of depth d kept three O(d)-length strings alive per ancestor level:
~6·d² bytes, ~14–15 GB at depth 60,000, live heap no output sink can avoid
(upstream's fix was driven by a 32 GB test process).

Ported verbatim in mechanism: `JsonFrame::Literal(String)` →
`JsonFrame::Delim { indent: usize, kind: JsonDelim }` (`Copy`, fixed-size),
indent rendered at pop time; plus the compile-time pin
`const _: () = assert!(!needs_drop::<JsonFrame>())` so an owning frame cannot
come back; plus upstream's module-level cost table (per-format output bytes
and per-frame retention, including why `AsciiTree`'s Theta(d²) live cost is
*not* fixable the same way — its prefix is not a function of depth alone) and
the full test set: four **byte-exact** JSON goldens (nested, truncated,
zero-premise, dangling-premises), the closed-form (bytes, lines) size formula
with a cross-check against real renderings, and the deep-chain regression
(depth 10,000 through a counting sink — output is inherently Theta(d²), so
the test streams and discards it and pins only the format, while the
heap shape is pinned at compile time). Output is byte-identical to the old
writer (the byte-exact goldens are the proof). One upstream comment carried a
wrong constant ("82 fixed bytes" where the validated formula needs 86);
corrected in the port.

### 2. `nixie-wasm/src/js_api/optimize.rs`: the objective-term guard pin (upstream v0.3.3, test-only)

`parse_objective_term` splices an objective string into `(simplify …)` and
accepts only a trailing `Command::Simplify`; with `define-fun-rec` now
parsable (the v0.3.3 port), a recursive definition must route to the
rejection arm, not slide through with its definition silently dropped. The
rejection path builds a `JsValue` and cannot run natively, so the pin asserts
the parse yields `Command::DefineFunsRec`, never `Simplify`. Fork's
`parse_objective_term` verified shape-identical before porting the test.

### 3. (drive-by, required by the verification bar) `cargo doc -D warnings` was broken on pristine main

Six intra-doc-link errors across `nixie-sat` (3), `nixie-solver` (1) and
`nixie-theories` (2) — links to private or out-of-scope items introduced by
recent sessions whose gates must have run `cargo doc` without `-D warnings`.
Fixed by de-linking to plain code spans (no semantic change). One of the six
was in this session's ported module doc; the other five are pre-existing.
