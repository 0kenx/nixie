# FP class propagation and exact symbolic refinement

The implementation in [FP_HYBRID.md](../FP_HYBRID.md) adds a searchable
symbolic fragment to the existing constant-folding FP path. Direct reasoning
uses value classes and order; arithmetic definitions are introduced as exact
BV circuits when a candidate violates them. It covers add/sub/mul, including
binary64 and all five rounding modes. This is a capability result, with no
claim of a measured search speedup or of deciding the standing QF_FP corpus.

## Defects uncovered by independent validation

The new circuit evaluator was compared against exact rational arithmetic,
which exposed defects in the existing rational helpers. Fixing the first
failure did not establish that the remaining layers were correct:

1. **Subnormal decoding.** `fp_value_rational` shifted by a negative exponent
   and used the wrong denominator direction. This could panic instead of
   representing a subnormal. Decoding now applies the signed power of two
   explicitly, with binary64's smallest positive/negative subnormal checked
   against exactly `±1/2^1074`. Normal, zero, and invalid-field paths have
   separate regressions.
2. **Rounding carry.** `rational_to_fp` stored an unbiased exponent after a
   significand carry. RNE of `31/16` in format `(3,4)` must yield 2, represented
   by `(fp #b0 #b100 #b000)`. The previous datum had exponent `001`. A second
   regression covers carry while the unbiased exponent is still negative.
3. **Directed overflow.** Saturation used `(1 << (e-1)) - 2` as the largest
   finite exponent field. The correct field is `(1 << e) - 2`. RTZ of 16 in
   `(3,4)` is 15, `(fp #b0 #b110 #b111)`, not exponent `010`. Both signs and
   every rounding mode are checked. Z3 4.16.0 independently refutes the two
   wrong-data examples above.
4. **Witness serialization.** Both basic and pretty SMT-LIB printers printed
   decimal exponent/fraction fields behind binary prefixes and omitted width
   padding. A witness for `x+x=3` printed `(fp #b0 #b3 #b4)`. Both paths now
   print `(fp #b0 #b011 #b100)`; direct tests include a fraction wider than
   64 bits. The public regression reparses the returned witness and checks
   it against the original assertion.
5. **Assertion stack depth.** The BV assertion walk's apparent explicit stack
   still called mutually recursive true/false assertion functions through
   `not`. Polarity now travels on the heap stack, including in the visit key.
   Direct BV tests exercise 20,000 negations with both SAT and UNSAT polarity
   and a shared Boolean reached with opposing polarities. The hybrid has its
   own 12,000-deep Boolean DAG regression and pins already-encoded truth
   variables directly.

Unsupported rational target formats now return `None` rather than using a
saturating/truncating integer conversion. Both folding and model-building
callers propagate that refusal. Public wrong-data regressions prevent a
shared evaluator defect from certifying its own wrong value as a witness.

## Layers checked

- Typed input collection validates result/operand sorts, literal fields,
  supported operators, and format bounds before any domain conflict is
  trusted. Unconditional fact extraction tracks Boolean polarity.
- Class transfer tables overapproximate every tiny-format arithmetic result;
  numerical comparison edges exclude NaNs, preserve signed-zero equality,
  and justify strict-cycle conflicts. Direct congruence reuses Nixie's EUF
  solver, with format and rounding mode included in function identities;
  IEEE equality never authorizes a datum merge. Separate regressions check
  congruent multiplication without SAT and opposite-sign IEEE-equal zeros.
- Arithmetic circuits follow Z3's unpack/alignment/normalization/rounding
  construction. Tiny formats are exhaustive across all modes and operations;
  binary64 cases include signed zeros, subnormals, normal boundaries, overflow,
  infinities, NaNs, and deterministic random bits. Asymmetric formats test
  intermediate exponent headroom. Rational validation is structurally
  independent of circuit construction.
- BV registration is bottom-up, including Boolean operands. Refinement uses
  one SAT instance, frozen variables, root backtracking, persistent encoding
  memos, and an adopted model snapshot. Every arithmetic node is refined at
  most once. An already-exact definition failing validation yields Unknown.
- The outer dispatch owns no persistent hybrid scope state. Public repeated
  checks and push/pop exercise model replacement and assertion removal.
  Model values retain original term IDs. Proof mode and unsupported resource
  limits retain the existing path.
- Shared arithmetic callers, both output printers, and the BV assertion
  primitive have direct tests so the new outer dispatch cannot mask them.

## Reproduction

Run the workspace verification gates and `bench/z3_parity/run_parity.sh`.
Current verification uses installed **Z3 4.16.0**; old 4.15.4 snapshots retain
their historical attribution. The standing suite includes five new FP cases:
unpinned binary64 addition, a negative square, symbolic rounding mode, a class
conflict, and the rational carry defect.

`python3 bench/differential/fp_hybrid.py --nixie target/release/nixie`
generates 300 deterministic tiny-format formulas containing arithmetic,
comparison, classification, and Boolean structure. Its JSON records the
comparator version, input digest, and each verdict-pair count. Unknown and
timeout are never counted as agreement. This is functional differential
testing, not a matched-null performance experiment.

169 SAT/SAT and 131 UNSAT/UNSAT, with no unknowns, timeouts, or wrong answers.

`12fca7e41810956a5587b8937b12484fcddef4e19cba6053bb212ae7d8d9c63e`.

tests passed**, 12 skipped; doctests; clippy with warnings denied; formatting;
and documentation with warnings denied through `.cargo/config.toml`.
