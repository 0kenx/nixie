## The port (cadical `analyze.cpp` 1152-1200)

When ≥ 1 resolution has completed, the antecedent exceeds 2 literals, and
the accumulated resolvent is absorbed into it, the antecedent is rewritten
in place — pivot literal + level-0-falsified literals dropped — and the
analysis **restarts** from the strengthened clause (cadical's restart
form).  `resolved == 1` additionally retires the original conflict clause
when the strengthened antecedent subsumes it (exact subset test, with the
`crn_11_99_u` promotion rule).  The pivot's trail reason is reset to
`Decision` on rewrite (chronological-BT safety).  The arm is inert under
any proof attachment (the pivot drop is justified by resolution against
the in-flight resolvent; cadical's LRAT mini-chain is not ported —
recorded deviation).

## The false-unsat (caught by the screen's verification gate)

The first implementation triggered on a cheap size comparison
(`counter + learnt < |A|`) that **undercounts the accumulated resolvent**:
resolved-away conflict-level pivots leave both accumulators while staying
`seen`.  It fired when the resolvent was NOT absorbed into the antecedent,
so the dropped pivot was unjustified and the "strengthened" clause was not
entailed.  The corpus screen surfaced it as 57 rejected cells across 13
files — direct verdict contradictions with model-verified baseline SAT
cells (`constraints_17` false `unsat` @ 956 conflicts vs baseline
model-checked `sat` @ 44 381; `frb65`, `mp1-klieber` false `unsat` ~1.3 k;
plus g2-slp, all three summle files, si2, j3037_10_mdd_b).  The 213 cells
the broken arm did file were purged.  In-process differential tests (380
paired random CNFs) had passed throughout — the instance class never hit
an *observable* contradiction; only the verified corpus screen caught it.

**Fix**: the fire gate is now the exact cadical condition — every marked
literal except the pivot's negation must already be a literal of the
antecedent (forcing the merged resolvent to BE `A \ {p}`; then the drop is
genuine self-subsumption and `A'` is entailed).  Pinned by three corpus
regressions (`NIXIE_SLOW_REGRESSIONS=1`): constraints_17 / mp1-klieber /
frb65 must never answer `Unsat` under the arm.

## Verdict

The amplitude mechanism works (circuit-class yields at cadical parity) and
is now sound, but the corpus aggregate sits on the wrong side of neutral
(1.016×), with the same per-family split as every restart-adjacent
intervention: the x9/Break/circuit/FmlaEquivChain class wins, the
restart-hungry class (rbsat/mp1/worker/mdp/noL) loses.  **Default stays
off**; `NIXIE_OTFS=1` is documented-negative-as-default infrastructure
with a real winner-class conversion (circuit_64in64out 0/5→1/5 at the cap,
constraints_17 −24 % conflicts).

The pattern is now measured across FOUR intervention families (margin
ladder, adaptive margin, tiered schedule, OTFS): the winner set is
essentially constant.  The recorded next shape for the restart-demand
split (per-class adaptation on a demand-axis signature, or portfolio
budget arithmetic) is in the tiered-port study; OTFS adds the datapoint
that *amplitude* interventions inherit the same split, because rewriting
antecedents mid-search is itself a restart-adjacent perturbation.
