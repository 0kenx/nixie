# OxiZ 0.3.4 migration audit

## Reference and scope

Requested scope: all missing features, without prioritizing one subsystem.
The upstream repository is `cool-japan/oxiz`; the fork's `origin` is not upstream.
The released `v0.3.4` commit is
`5d33041fb81cc2306969e86a3d37b599578a4e1f`; branch `0.3.4` was fetched at
`41439c5194ebbb80649505a1116ef4ea2716dd0b`. Their trees are identical.
Relative to `v0.3.3`, the release changes 367 files (82,311 added lines,
6,214 removed lines). The August audit's statement that 0.3.4 contains only
version/documentation changes described an earlier branch tip and no longer applies.
The starting fork commit was `af14b6d2`.

This is a capability migration, not a wholesale merge: the fork has substantial
independent correctness, exact-arithmetic, model-finding and SAT work that must
survive. An absent upstream filename does not establish an absent feature.

## First slice: parser, literal boundaries, quantified theories

- Added the seven SMT-LIB overflow predicates: `bvuaddo`, `bvsaddo`, `bvusubo`,
  `bvssubo`, `bvumulo`, `bvsmulo`, and `bvnego`. Operands are width-checked;
  doubling a multiplication width is checked; constants remain exact beyond
  64 bits. Sign extension uses a logarithmic-depth concatenation DAG.
  Consulted Z3's `bv_decl_plugin.cpp` and `bv_rewriter.cpp` for semantics.
- Added checked `Lit::try_to_dimacs`. Invalid variable encodings fail before
  allocation or truncation, in release as well as debug builds. DIMACS parsing,
  literal construction/conversion, bulk variable allocation, and output validation
  each enforce the same representable boundary. Writer validation precedes output.
- Migrated ground datatype discovery under binders and generated instances.
  Discovery respects lexical binding; independent ground terms under a binder
  receive axioms, while bound terms wait for instantiation. Ground roots and axiom
  deduplication entries roll back with their clauses and reset with the solver.
- Migrated complete guard-region sampling: adjacent integer/BV values, exact
  symbolic real neighbours and pairwise midpoints, polarity-sensitive eligibility,
  and ground-premise peeling. Preserved the fork's rejection of nested binders
  and its separate constructor-table certification ownership.
- Migrated unnamed array-index regions, including enum/declared-sort handling
  and conservative rejection when no complete representative set is available.
  Lexical index collection distinguishes free and bound uses of the same symbol.
  An unresolved scalar index or unrepresentable rational boundary declines
  certification instead of silently deleting a required region.
- Plan all quantified tuple sets before substituting bodies. Reject exhausted
  instantiation budgets rather than skipping an uncertified quantifier.

## Root-cause layers checked

The quantified datatype pins Q1/Q2/Q5 and T00088 returned false `sat` before
this migration; Q6/Q7 returned `unknown`. The focused tests now expect `unsat`.
Ground datatype pins F01–F16, N01–N16, D00085 and D00087 already agreed with Z3
on the starting binary, so those upstream implementations were not overwritten.

The array default regression independently exposed these layers:

1. Certification needs points outside named store indices. The finite relevant
   set alone cannot extend a model of `store(const 0, 0, 1)` into an array that
   reads 1 everywhere.
2. Generated ground instances were absent from array-axiom discovery. Registered
   roots now include arrays and are collected as conditional structure, never as
   unconditional equalities/disequalities.
3. Array refinement ran only for quantifier-free goals. It must run before either
   result path accepts a candidate. In the 7-bit index reproducer, all 128
   instances had already been emitted; missing samples were not its only defect.
4. A Real-indexed goal with no ground read has an empty initial relevant set.
   Goal-based region representatives must also seed the first complete set,
   rather than being available only after ordinary saturation.
5. Scoped roots, axiom caches, SAT clauses and theory state must agree after
   push/pop/reset and refinement rebasing. Regression scripts check both the
   failing scope and satisfiable scopes before/after it.
6. A false instance of a guarded universal implies the negation of its guard,
   not the empty clause. All instance paths retain the guard; domain/pigeonhole
   heuristics requiring asserted facts run only for unconditional instances.

Each layer was inspected after the outer reproducer first improved. Focused
unit/integration tests protect guard polarity, lexical name shadowing, exact
boundary handling, datatype reset/pop, conditional quantifiers, and arrays over
BV/Int/Real indices.

## Remaining audit queue

The overall migration is not complete at this checkpoint. Remaining capability
families include symbol reservation/printing and get-value spelling; allocator
zero-size/alignment and ownership; datatype builder/folding APIs; root-persistent
SAT definitions and formal harness changes; BV budgets/bridging and mixed
arithmetic; array model publication/completion; and the remaining solver
regression corpus. Refactors, version bumps and expect-removal-only changes
must be distinguished from missing behavior rather than counted as features.

- Every ground encoding entry discovers array terms under opaque function and
  arithmetic/BV operands. All former depth-zero encoder bypasses now use the
  guarded entry. Bound bodies wait for ground instances, and push/pop restores
  the discovery flag with its roots. This fixes `#P2b-33`; merely collecting more
  reads inside the refinement pass was insufficient because the pass never ran.

  Other internal mint families remain follow-up work.
- `Command::GetValue { terms, keys }` carries exact source expressions through

  deliberately avoiding upstream's empty-string fallback for invalid offsets.
- Symbol formatting covers terms, binders, datatype declarations' names, sorts,

  sort resolver agree about bars, spaces and parentheses inside quoted names.

## Third slice: allocator alignment and ownership

The upstream arena/region fixes align allocation addresses (not offsets),
reserve nonzero backing storage for zero-sized requests, and honor alignments
larger than the default block alignment. Checked offset arithmetic prevents
wraparound; region block growth saturates before layout validation. Arena also
exposes a fallible `try_alloc` entry point.

Independent review found a deeper existing safe-API defect: `ArenaHandle` was
copyable and had no lifetime tying it to its arena. Safe callers could therefore
retain freed pointers after reset/drop, or obtain aliased mutable references
from copied handles. Handles now uniquely own their values and borrow the
arena. Allocation uses interior mutability so multiple live handles remain
usable; reset/clear require exclusive access. Both arena and region handles
run destructors exactly once. A slice initialization guard drops only the
initialized prefix if a user-provided `Clone` panics.

The reviewed layers were allocation layout, address alignment and offset bounds,
zero-sized pointer validity, chunk growth and movement, handle uniqueness and
lifetimes, reset/drop ordering, and partial initialization on unwind. Twenty
focused release tests pass, including upstream alignment/zero-size regressions
and new destructor/clone-panic regressions. Compile-fail doctests pin rejection
of an outliving handle, reset with a live handle, and copying a handle. The
allocator types are used only by their example and tests in this workspace;
solver `TermArena` and clause arenas are separate implementations.

Third-slice release verification passed: all-feature build, 12,449 nextest tests
(18 skipped), 117 doctests (31 ignored), Clippy across all targets with warnings
denied, formatting, and rustdoc with warnings denied. These checks used release
optimization with LTO disabled and 16 codegen units. This slice does not change
solving, theories, proofs, quantifiers or NLSAT, so its verification does not
claim a new parity/performance measurement.

## Fourth slice: datatype construction and integration

Migrated constructor equality decomposition/disjointness, bounded distribution of
selectors/testers/equality over datatype ITEs, spur-based accessor builders, and
whole-term constructor-accessor folding. The rewrite uses one explicit heap
worklist across alternating constructor/ITE equality nesting. Shared constructor
DAG components and conjunctions are visited once; per-level flattening would
otherwise expand a shared binary DAG exponentially. Accessor folding performs one
bottom-up traversal, preserving binder names and pattern annotations. A selector
applied to the wrong constructor remains underspecified. Reference semantics were
checked in Z3's `datatype_rewriter.cpp`.

The independent layers examined and defects found are:

1. Builder simplification, substitution rebuilding and raw AST input. The upstream
   third-color ITE pin is protected both through parsed/builder input and through
   an explicitly unfurled equality atom. Deep constructor, alternating ITE,
   negation, accessor and shared-DAG tests exercise the rewrite separately.
2. Constructor congruence. Its conclusion must remain an equality atom; using the
   new decomposing builder would merely repeat the field-equality premise and
   lose the equality-engine merge. `mk_eq_atom` provides this explicit boundary.
3. Declaration name ownership. Parser/TLA declarations used term-interner keys,
   while the standalone datatype theory and public SortManager API used
   sort-interner keys. Numeric keys from these independent tables can collide.
   Stored declarations now consistently use SortManager keys. A new
   `TermManager::declare_datatype` converts term-local input names; every consumer
   resolves declaration names through the sort manager. A regression deliberately
   gives the two tables different insertion histories and tests both APIs.
4. Set integration. The existing tuple-member and query-only join model tests
   exposed opposite membership assignments for elements equated by late datatype
   lemmas. Assert-time set reduction cannot see those equalities. Candidate
   refinement now asserts guarded membership congruence and re-solves, using the
   ordinary scoped clause/memo journals. Budget exhaustion returns Unknown. The
   focused regression introduces equality after reduction and repeats push/pop;
   CVC5's equality-engine registration of SET_MEMBER and APPLY_CONSTRUCTOR was
   consulted independently.
5. Model readback. The growing TLA sequence test solved its step-3 query quickly
   (7,100 decisions, 11,602 propagations, 67 conflicts in the diagnostic run),
   then hung decoding the array-backed sequence. Tracking only alias hops missed
   cycles through store bases. Merely tracking all links was also insufficient:
   evaluating whole store DAGs could manufacture a longer store chain on each
   hop. Readback now follows one assignment at a time, inspects stores without
   expanding their bases, and tracks every visited link. Conditional array branches are followed only
   after their condition is decided; unresolved ITEs are never unfolded.
   Known writes remain
   readable; cyclic unresolved reads remain symbolic. Multi-store/alias-cycle and conditional-cycle
   regressions protect the lower-level model API independently of the TLA test.

6. The next full run exposed a distinct set-reduction defect: its final
   congruence pass minted memberships for equality-chain intermediates after
   defining membership and set-equality axioms. In the TLA function-domain pin,
   `(select f 2)` was such an intermediate; its unconstrained membership atom
   could be true even though the read was 20 and the domain was `{1,2}`. The
   pass now only relates elements whose definitions exist. Candidate refinement
   handles transitive equality between those elements directly. A model-query
   regression and a late equality-chain/push-pop test protect these two layers
   separately; the existing trace test remains unchanged.

The initial full-suite experiment found six expected term-shape changes, two
real set-model regressions, and the sequence readback timeout. Shape tests now
expect the equivalent folded constants; tests intended to exercise the standalone
rewriter/theory deliberately construct raw nodes instead, preserving independent
coverage. These failures were investigated independently; the final gates below were
rerun after all fixes.

## Fifth slice: permanent SAT clauses and restoration

Added `Solver::add_clause_at_root`: clauses belong to the base assertion scope,
units have a replay journal, and a conflict caused by temporary facts is cleared
when those facts are popped without deleting the permanent clause. Conflicts
against permanent facts and explicit empty root clauses survive every pop.
Reset clears the journal. The implementation preserves the fork's binary graph,
clause feature instrumentation, level-aware attachment and proof identifiers.
It uses the fork's existing backtrack-and-rescan rule rather than copying
upstream's backjump helper against a different trail scan contract.

Independent layers checked beyond the new entry point:

1. Destructive elimination only runs at base scope. When a later mention voids
   a pure-literal or BVE reconstruction promise, its retired original clauses
   must therefore be restored permanently, even if the mention is scoped.
   Previously restoration used ordinary `add_clause`, which attached those
   originals to the temporary scope while permanently voiding reconstruction.
   A regression eliminates a pure variable, reintroduces it inside push/pop,
   and checks the original obligations after the pop.
2. Restoration may encounter another eliminated variable. A heap worklist now
   restores the full closure; it cannot stop on a temporary conflict and lose
   the remaining obligations. Independent tests exercise a pre-existing scoped
   conflict and a 2,000-variable restoration chain. Consulted CaDiCaL's
   `restore.cpp` for restoration closure and `clause.cpp` for original-clause
   attachment and original-unit bookkeeping.
3. Root-clause proof tests exposed an ordinary insertion defect: a parse-time
   conflict could emit an empty LRAT clause before delayed implied-unit proofs
   existed, producing zero hint identifiers. Conflict finalization now flushes
   those implications in assignment order. A regression using only ordinary
   clauses protects this shared path independently of root-unit replay.
4. Popped pending implications must not later cite deleted reasons. Delayed
   flushes check that the assignment and reason are still live; pop invalidates
   removed assignments' unit proof identifiers, and reset clears pending work.
   A separate LRAT checker regression exercises removal before the first solve.

Focused validation includes nested scopes, conflicting root units and clauses,
post-model clause insertion, reset, 300 seeded operation sequences compared with
an exhaustive 10-variable oracle (including model checking), and independently
checked LRAT proofs. These tests verify scope semantics and proof validity, not
performance claims. Full landing results follow below.

All release gates passed: build, 12,489 nextest tests (18 skipped), 117 doctests
(31 ignored), Clippy with warnings denied, formatting, and documentation with

## Sixth slice: assumption search and bit-vector scopes

The embedded BV solver now retains circuit definitions and checks scoped
assumptions. Equality and signed/unsigned comparison gates and disjunction
selectors are memoized. Constants have separate literal-definition and scoped
assertion APIs, preserving the fork's constant folding, deferred Boolean IR,
unified main-SAT circuits and arithmetic operator implementations. Boolean
circuit construction uses an explicit postorder worklist; `bv_ite` reports
unsupported selectors or incompatible operands instead of silently building
nothing. The upstream opaque-leaf registry and circuit introspection APIs are
present; their use in the theory-combination bridge is a subsequent slice.

Independent defects found along the migrated path:

- SAT assumption search installed assumptions only once, then backjumped to a
  fixed level of one. Restarts could remove them without reinstallation; with
  no assumptions, a needed jump to level zero was prohibited. The decision
  loop now assigns one level per assumption (including already-implied ones)
  and restores missing assumptions before any free choice. This follows
  upstream `assumption_search.rs` and CaDiCaL `decide.cpp`'s pseudo-level
  protocol. Learned clauses remain consequences of permanent definitions.
- Failed-core deduplication used variables instead of signed literals, losing
  one hypothesis of `[x, not x]`. Cores now preserve polarity and translate
  substituted literals back to the caller's assumptions. Separate tests check
  complementary assumptions and a real equivalent-literal substitution.
- A base conflict found by assumption search must remain a base conflict on
  later checks. It is latched and carries a checked LRAT refutation. The fork's
  proof-aware learning path is retained rather than copying upstream's blanket
  LRAT disable. Root units also replay after the fork's explicit probe-trail
  restoration API, not only assertion pop.
- A first scoped constant previously replaced the term's permanent bit mapping
  with constant wires. Scoped assertions now constrain free bits; literal
  definitions alone may use reserved constant wires. Constant-folding tests
  now explicitly use the literal API and retain their original expectations.
- A pinned Boolean selector was a hypothesis missing from BV conflict
  explanations. Explanations now use failed assumptions and include selector
  pins; unlabelled assumptions fall back to all recorded hypotheses.
- Plain Boolean selectors were omitted from the lazy theory shadow trail.
  They now replay at their original level, and the final candidate check checks
  every active BV assumption, including a selector assigned after the last BV
  atom. Unfinished embedded checks cannot silently approve the candidate.
- The fork's sorting-network equality/distinct shortcuts are assertions too:
  their journals now roll back with scopes. A focused test exercises both
  directions, so permanent circuit retention cannot hide stale shortcut facts.
- Wide model groups use exact `BigUint` values and widths. Model-equality
  extraction likewise includes width and never merges different BV sorts.

Focused evidence: 76 SAT/BV tests passed, including independent brute-force
scope/core checks, 400 randomized assumption instances, repeated searches and
clause additions, selectors and wide values. A further 22 proof/core tests and
13 SMT integration/differential tests passed. Subsequent tests also cover deep
Boolean circuits and the fork-specific shortcut and constant cases. Full

## Seventh slice: resource budgets

Migrated SAT decision ceilings and explicit deadlines, the BV conflict-budget
accumulator, `Context::bv_conflicts_spent`, and the deterministic embedded-check
counter/option. The upstream 250,000-check cap is preserved; the user option can
lower it. The deadline is an explicit resource limit, never a heuristic input.
No clock is read by the new SAT poll when no deadline is configured. Consulted
CaDiCaL `limit.cpp` alongside upstream's budget implementation.

The fork has an additional arithmetic repair loop outside `check_core`, so the
budget is armed at the public query boundary, after the unchanged-goal cache.
Every SAT/theory/BV repair round shares that allowance and deadline. The fork's
unified BV encoding spends the outer SAT budget; embedded encoding spends the
separate BV allowance. Tests explicitly select embedded mode where they measure
its counter, rather than assuming upstream's sole encoding architecture.

Independent layers checked and corrected:

- SAT ceilings are absolute cumulative counts. The previous caller subtracted
  already-spent conflicts and passed that remainder as an absolute ceiling,
  shortening later searches twice. Each query now adds its allowance to the
  current counter, and settings that disable a limit explicitly clear it.
- Theory conflict limits likewise start at the query's existing counter, and
  are not replenished when the manager is rebuilt. SAT decisions are bounded
  inside the search, including the pure-Boolean fast path and assumptions.
- Embedded resets zero SAT statistics but preserve the BV accumulator. Each
  probe gets only the remaining allowance; only a new public query re-arms it.
- The manager receives the original deadline on every reconstruction. The
  detached pure-Boolean watchdog is replaced by the same deadline-aware SAT
  poll, eliminating a late watchdog interrupt after its guard had dropped.
- An interrupted equality notification must not republish equalities from a
  previous model. Notifications clear those candidates before a new check;
  a regression first establishes shared equalities, changes the assignment,
  interrupts the next solve, and requires an empty candidate set.

Focused evidence: the migrated SAT/BV/script tests passed (25 tests), followed
by nine transition/accounting tests, including independent conflict and decision
re-arming checks. The ignored unbounded multiplier control also passed `unsat`.
Release build, **12,552 tests** (19 skipped), 117 doctests (31 ignored),
Clippy, formatting and documentation all passed. Installed Z3 **4.16.0**
parity remained 175 agreements, zero wrong answers and two inconclusive cases.
The broad replay remained 174 correct, five wrong and one inconclusive.
The perf gate against `6da08209` passed at a 300-second cap on all nine
core and three available external cases: matching verdicts, conflict and
decision ratios **1.000**, secondary wall ratio **0.97**.

## Eighth slice: bit-vector / EUF exchange

Migrated opaque BV leaves for UF applications and array reads, and upstream's
bidirectional equality exchange. EUF equalities carry explanations into the BV
scope. BV model partitions are checked in a temporary EUF scope; a refutation
produces an explained disjunction, never a permanent guessed equality.

## Twelfth slice: quantifier positions, finite expansion, and certificates

The polarity-complete upstream guard is migrated: positive/negative occurrences
receive the appropriate universal definition or Skolem witness, and equality,
xor, conditional tests, and term positions receive both directions. Obligations
are processed with an explicit heap worklist, bounded by depth and total work;
a missing definition marks the encoding incomplete. Source assertions and
named-core identities retain the user's terms. Every remaining unowned
quantifier is checked at the common result exit as well as the MBQI exits.

All four instance paths (MBQI, e-matching, blind, finite-domain) now prepare
newly ground ITEs and quantifiers. A conditional instance guards even its own
top-level binder; its outer SAT guard remains on the clause. Prepared quantified
instances are memoized with a scope journal, and pop removes their definitions
and memo entries together. Atomic binder sorts are seeded after assertions have
contributed their ground inhabitants and before the search checkpoint, preventing
query-local seeds from being repeatedly minted and rolled back.

## Thirteenth slice: array ITE identities and arena-safe API terms

The array interface did not install the identity of an array-valued conditional
with its selected branch. `(distinct a b (ite p a b))` consequently returned
false `sat` for both Int/Int and BV1/BV1 arrays, in both eager and lazy modes;
Int, uninterpreted-sort, and BV3 controls were already correct. The baseline
matrix and Z3 4.16.0 comparison are retained with the verification artifacts.

The migration follows Z3 `context::internalize_ite_term`: for every ground
array `I = ite(c,t,e)`, assert `not c or I=t` and `c or I=e`. The original
term is its EUF name, avoiding a second proxy array and spelling map. The
shared-interface worklist discovers nested term positions without native
recursion and stops at binders; instantiated ground terms use the same path.
Both polarities of a compound Boolean condition are encoded. Definitions have
a dedicated scope journal and reset state. Their equality atoms are registered
as conditional ground roots so array read congruence and extensionality can
see them without treating either branch equality as unconditional.

Independent layers inspected: the existing non-Boolean hoister intentionally
leaves BV ITEs to their circuits; array read axioms handle read-through-ITE but
cannot establish an array's identity; `distinct` introduces negative equality
atoms and therefore cannot rely on positive-equality expansion; the array
collector's ITE case assumed these branch equalities existed, and its active
EUF filter applies guarded read consequences to the newly registered atoms.
The SAT clauses are theory identities and never depend on candidate values.

Tests cover both theory modes, negative equality, nested conditionals,
functions taking arrays, nested array sorts, quantified instances, all fourteen
upstream ground spellings, and repeated push/pop/reset transitions. The reset
regression independently exposed `Context::reset` clearing `logic` but retaining
`logic_was_set`, incorrectly refusing a new session's `set-logic`. It now clears
both; a direct test retains the repeated-logic rejection across
`reset-assertions`, and permits the new logic only after full `reset` (matching
Z3's `cmd_context::reset`).

The first full run exposed another independent soundness defect when the ground
interface stopped silently skipping missing term IDs. The Z3 facade created
terms in `Z3Context` but passed their IDs directly to an unrelated `Context`
arena. Its parameter-pipeline test had previously accepted a formula whose
nodes were absent; the honest missing-term check correctly changed that answer
to `unknown`. The repair transfers the actual DAG, with an exhaustive match on
all 154 term variants, remapped symbols/sorts/field IDs, trigger terms, and
recursive datatype definitions. Term and sort walks use explicit heap stacks.
Recursive datatype placeholders are created before traversing their fields;
conflicting definitions fail rather than overwrite the target declaration.
The term and sort string interners are handled separately (uninterpreted sort
names belong to the former, datatype/parameter names to the latter).

The facade now distinguishes context-built Boolean handles from explicit
solver-local `Bool::from_id` handles, even when their numeric IDs collide.
`Bool::from_context_id` wraps an existing context term; callers that formerly
constructed a `Bool { id }` literal must use one of these constructors. This
small API change is necessary to remove an otherwise ambiguous arena choice.
The context must still match the one supplied to a constructor; a formula from
a different context is rejected as `unknown`. Import errors are scoped and
cannot expose an old model. Free symbol declarations are registered for model
output, and all `Z3Config` solver settings are copied at construction.

Tracing the remaining facade paths found assumption checks bypassed publication
state: the raw check could leave the preceding model/core visible. They now
invalidate stale results, apply the context's array gate, resolve aliases, and
record the new verdict/assumptions. Assumption cores retain the original arena
handles; returning the full unsatisfiable assumption set is sound without a
minimality claim. Push/pop/assert and mutable context access invalidate them.
Focused tests cover a genuinely contradictory integer formula, source/target
ID collisions, construction after a prior solve, model publication, core replay,
invalid imports and pop recovery. Core tests cover interner skew, recursive
array/datatype sorts, trigger-only children, finite-field ID skew, 129-bit
constants, and a 20,000-level DAG on a 1 MiB stack. The focused facade suite
passed all 94 tests.
